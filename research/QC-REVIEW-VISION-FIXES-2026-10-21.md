## Partial findings — exact residual

- **H3** — Audio is fixed end-to-end for new sessions (aggregate at stop → report). The face half is **not** fixed: `_face_aggregate` requires `face.visible is True` (`service.py:694`), while the worker emits `face.visible = presence_proxy(...)` as a float 1.0 (`vision/worker.py:1545-1553`, `vision/face_math.py:72-86`); every detected-face session therefore stores `frames_visible=0` and `*_mean=None` (probe: visible 1.0 → 0, True → 5). Pre-fix stored sessions also still get a false audio negative because `vision_only_report._audio_payload`/`_face_payload` (`:366-374`, `:464-472`) look only at `summary`/`session`, never at `frames.jsonl`.
- **H8** — The misleading promise is gone, but the outcome is still not computed. `vision/pose_math.py` has no hold-time, rep or gait metric; the only hold reference (`norms.py:198-217`) and the `hold_s_*` candidates (`vision_report.py:131-138`) cannot be produced by any stored field. The guide correctly tells the operator to use a stopwatch and a free-text mark.
- **H10** — The window is time-based and comparable across fps (probe above), and `summarize_frames` now emits `sway_baseline_s`, `sway_baseline_frames`, `trunk_x_range`, `trunk_y_range`. The printed report does not state the window and does not show the total range; only the residual `trunk_sway_*_range` cells are rendered (`vision_report.py:1055-1097`).
- **M3** — The sync dict exists and the report prints method + spans. `_meta_list` (`vision_report.py:904-925`) silently drops `measured: false` and the `note` (“offset/jitter not measured”), so the quality header still does not state that no offset was measured. It also labels a camera-only summary “Camera-plate sync”.
- **M6** — Operator marks are on the frame clock now (`vision_mark` `t_rel` probe: trial mark 1.5 s; vision-only mark 3.5 s). Automatic frame events are not: `_append_vision_only_frame` passes them to the store without `t_rel`, and `VisionSessionStore.append_event` falls back to wall-clock session start. A first frame delayed by 2 s still shifts `pose_lost`/`audio_*` events by about 2 s.
- **L1** — README fixed; the stale 591 in `research/VISION-INTEGRATION-SPEC.md:106` remains.

## New regressions introduced by the fix wave

1. **CRITICAL — face aggregate rejects every real detected face.** `_face_aggregate` only counts `face.get('visible') is True` (`service.py:691-695`), but the worker's real payload sets `face.visible` to a **float** presence proxy (`vision/worker.py:1545-1553`, `vision/face_math.py:72-86` returns `min(1.0, count/468)`), and only the no-face branch sets the bool `False`. Probe: five rows with `visible: 1.0` → `frames_visible=0`, `mouth_open_mean=None`; `visible: True` → `frames_visible=5`, mean 0.2. Consequence: every real face session reports “Frames with a face: 0”, 0.0 %, and no proxies — a false negative about recorded data, the same class of error H3 was meant to remove. Existing aggregate fixtures use `visible: True` (`tests/test_vision_only_sessions.py:677-680`), so the suite cannot see it. The condition should accept `True` or a finite number > 0 (as `vision.js:209-218` already does).
2. **Zero keyword categories are printed as matches (low/medium).** `_audio_aggregate` initialises all three categories to 0 (`service.py:643`, returned at `:662-677`); `_merge_audio` accepts numeric zeros, so `flag_counts` is non-empty even with no hits. Both renderers then print them: `vision_report.py:796-801` → “keyword match: pain … x1, comprehension … x0, keyword match: stop … x0”; `vision_only_report.py:442-445` → “× 0” list items. Probe confirmed on a session with one pain hit. The report should filter zero counts; the suite does not assert their absence.
3. **Face aggregate bookkeeping leaks into the face-proxy table (low).** `service._face_aggregate` emits `frames_with_face_data`, `frames_total`, `visible_pct` (`service.py:702-714`). `_merge_face` (`vision_report.py:559-593`) treats every numeric key except `frames_visible`/`frames` as a mean, so both reports print “Frames with face data: 10.000”, “Frames total: 10.000”, “Visible pct: 100.000” as if they were landmark proxies (`vision_report.py:828-836`, `vision_only_report.py:492-494`). Values are correct but labels/formats are misleading and duplicate the “Frames with a face” row.
4. **Short stored segments are reported as “no segmentation stored” (low).** `_vision_segment_summaries` drops groups under 10 frames (`service.py:2456-2457`) and returns `[]`; `_angle_table` then prints “No per-test segmentation was stored for this session” (`vision_report.py:1091-1096`), although `session.json` does contain the segment rows. A 5-frame segment is unlikely but the wording is false when it happens.
5. **Consent lanes can survive a failed session start (low, privacy edge).** `vision_only_start` applies `_vision_ensure_flags` before `vision_store.create` (`service.py:2021-2025`) and does not roll back if `create` raises; `vision_only_stop` restores only if `finish` returned a document (`:2153-2172`, with `_vision_flags_before_session` cleared in `finally`). A disk error can leave the microphone enabled with no session; `vision_audio(False)` is the only recovery.
6. **Stale lifecycle comments / ctypes handle typing (low, no observed failure).** `vision/manager.py:349-353` still says stdin is a pipe even though `:427-429` uses `DEVNULL`; `--parent-watch` help (`vision/worker.py:1698`) still says “closes stdin”. `_parent_alive` (`vision/worker.py:873-881`) calls `OpenProcess` without `restype=c_void_p`/`argtypes`; the probe works on this host (self True, bogus PID False), but handle truncation on 64-bit Windows is a latent risk.

One new **critical** regression was found: the face-visibility condition in `_face_aggregate` is too strict for the worker's real float proxy. It does not corrupt the kinematics or plate numbers, but it makes every face-enabled report falsely show zero face data. The other five regressions are low/low-medium report/cleanup issues.

## Verdict

The three number-corrupting defects that made the original review say “not safe tomorrow” are genuinely fixed: plate-trial pose coverage is real (C2 probe 50 %), angles are aspect-corrected (H1 probe 5.66° → 10.0°), audio flags no longer fabricate categories (C1 probe `{'pain': 1}`), and COP–COM now filters both branches (H6 probe rate-invariant). Seven of the ten HIGH items are fully fixed (H1, H2, H4, H5, H6, H7, H9); H3, H8 and H10 remain partial on the specific residuals above. The reports no longer claim valgus change scores or a 5–10° band, the plate-only COP–COM block renders without a camera, and consent now defaults off and is stored per session. The suite is 1114/1114 green.
